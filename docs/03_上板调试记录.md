# 上板调试记录 · M2（OV5640 采集 → VGA 直显）

> 阶段：M2 采集链路验证
> 目标：戴尔 VGA 显示器上出现 OV5640 实时清晰画面
> 状态：⏳ 待上板验证

---

## 1. 上电顺序

1. **断电**状态下插好扩展板、OV5640 模块、VGA 线到戴尔显示器。
2. 确认电源极性与电压（VCC_IN 5V），**反接会烧核心板**。
3. 上电，接 JTAG 下载器，Program Device 下载 `build_flat/ct_top.bit`。
4. 按下表读 LED，再看屏幕。

## 2. 三种画面状态（核心判据）

`ct_top` 会统计"这一帧有没有写进非零像素"。连续 1 秒没有，就把画面切成 FPGA 内部 8 色竖条（白/黄/青/绿/品红/红/蓝/黑）；一旦摄像头出图，立即切回实时画面。

| 屏幕内容 | LED2 | LED1 | 含义 | 问题在哪 |
|---|---|---|---|---|
| **摄像头实时画面** | 亮 | 亮 | 采集 + 缓存 + 显示全通 | 无，M2 可签核 |
| **8 色竖条** | 灭 | 亮 | 显示通路正常，但完全没有 VSYNC | 摄像头侧：XCLK/供电/复位/SCCB 配置失败 |
| **8 色竖条** | 亮 | 亮 | 有 VSYNC，但像素全为 0 | 窗口/格式/曝光配置错 |
| 纯黑 + 显示器"无信号" | — | — | VGA 时序或 RGB 线序问题 | 先查 VGA 排线，再查 hsync/vsync 极性 |
| 纯黑 | 灭 | 灭 | SCCB 卡住，序列没走完 | 查 SCL/SDA 上拉与接线 |
| 纯黑 | 灭 | 亮 | MMCM 未锁定 | 时钟/约束问题 |

> ⚠️ **LED2 不能当作"摄像头正常"的证据**。如果传感器把 DVP 引脚设成了输入
> （`0x3017/0x3018` 写错），K17 悬空，噪声边沿照样能把 `vs_seen` 置起来、LED2 照样亮。
> 所以 LED2 亮只代表"PCLK 上有边沿"，不代表能出像素。真正可信的是屏幕：出画面才算通。

## 3. 其余屏幕现象速查

| 现象 | 最可能原因 | 处置 |
|---|---|---|
| 画面能出但整体偏色 | RGB565 字节序反了 | 改 `ov5640_capture.v` 里 `{b1, data}` 为 `{data, b1}` |
| 画面上下/左右反了 | 镜像位不对 | 改 `0x3820 / 0x3821`（当前 0x41 / 0x07） |
| 画面斜条纹/错位 | PCLK 采样相位不对 | 改 `0x3035/0x3036` 降低 PCLK，或改 PCLK 下降沿采样 |
| 画面正常但有横向撕裂线 | 单缓冲帧边界（已知，接受） | 无需处理 |
| 画面比例变形 | 摄像头窗口不是 4:3 | 核对 `0x3808~0x380B` = 640×480 |

## 4. 分步定位（当屏幕显示 8 色竖条时）

### 4.1 SCCB 是否通

- 用示波器看 `J18(SCL)`：每写一个寄存器是 **4 字节 × 9 拍 = 36 个时钟**。
- 看 `G20(SDA)`：SCL 低期间变化；ACK 槽应被从机拉低。
- LED3 亮 = 出现无 ACK：先量 SDA/SCL 静态电平，**空闲都应为 3.3V**。

### 4.2 摄像头是否在出时钟

| 测点 | 期望 | 没有时的含义 |
|---|---|---|
| `F20` XCLK | **24MHz** 方波 | 引脚/位流问题（MMCM CLKOUT2） |
| `E19` PCLK | 约 **56MHz** 方波 | 配置没生效，回到 4.1 |
| `K17` VSYNC | 约 30Hz 正脉冲 | 有 PCLK 无 VSYNC → 窗口/VTS 配置 |

### 4.3 打开传感器内部自测图案（二分法）

把 `rtl/ov5640/ov5640_cfg.v` 第 `9'd90` 条改成 `0x82`：

```verilog
9'd90 : cfg_rom = {16'h503D, 8'h82};   // 0x82 = 传感器内部彩条
```

重新综合下载：

- **传感器彩条能出** ⇒ 采集/缓存/VGA 链路全通，问题在镜头、曝光或窗口。
- **传感器彩条也不出，但 FPGA 彩条正常** ⇒ 问题在传感器配置或 DVP 数据线。

## 5. 现场需核对的寄存器（当前表已被验证为合法的值）

| 寄存器 | 当前值 | 作用 | 不对时的现象 |
|---|---|---|---|
| **0x3017** | **0xFF** | PAD 方向：[6]VSYNC [5]HREF [4]PCLK [3:0]D，1=输出 | 写 0x00 → 传感器不驱动任何线 |
| **0x3018** | **0xFC** | PAD 方向：[7:2]D[5:0]，1=输出 | 同上 |
| 0x3808~0x380B | 0x02/0x80/0x01/0xE0 | 输出 640×480 | 分辨率/比例错 |
| 0x380E/0x380F | 0x03 / 0xD8 | VTS = 984（30fps） | 帧率不对 |
| 0x4300 | 0x6F | RGB565 输出 | 偏色 / 像 YUV |
| 0x3035/0x3036 | 0x11 / 0x69 | PLL（24MHz 标定） | PCLK 频率不对，斜纹 |
| 0x3820/0x3821 | 0x41 / 0x07 | 镜像翻转 | 画面反 / 异常条带 |
| 0x3C04/0x3C05 | 0x28 / 0x98 | AEC 曝光上限 | 上限过小 → 全黑但有同步 |
| 0x4202 | 0x00 | 开流 | 不写 → PCLK 在跑但无数据输出 |
| 0x503D | 0x00 | 测试图案 | 0x82 = 传感器彩条 |

## 6. 构建期报错速查

### 6.1 `module 'xxx' not found` —— 不是代码错，是文件没登记

往 `rtl/` 里加了新模块后，`.xpr` 的文件列表不会自动更新。在 Vivado GUI 的 Tcl Console 执行：

```tcl
source {D:/ebaz4205/scripts/refresh_fileset.tcl}
```

### 6.2 `requires 18 connections, but only 17 given`

`MMCME2_BASE` 有 18 个端口，漏接的是 `CLKOUT6`。
